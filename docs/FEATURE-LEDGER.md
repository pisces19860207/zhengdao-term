## 一、现状（这个 App 是什么）

一个**只有终端**的 App：PTY ＋ rootfs 环境 ＋ 终端 UI。不含抱朴（对话/玄览/知识库），
不含法典与治理机制——那些在主仓 `zhengdao`。两仓**永不合并**。

- 包名：`com.example.zhengdao.term`
- 入口：`term/MainActivity`（落地页：授权 / 进终端）
- 核心：`:app` ＋ `:terminal-core`；`libs/zhengdao-core-2.2.1.aar`、`libs/zhengdao-native-2.2.1.aar` **随仓**
- 环境包：**本仓 Releases** `rootfs-13.7-2026.10.28`（**八件套**：包＋copyright＋manifest 各带 `.sha256`，
  加 `rootfs-index.json` 511B 与 `rootfs-index.json.sig` 88B；索引与签名 2026-10-28 09:49 重签，GitHub API 实测）
- CI：自包含（assembleDebug ＋ 单测 ＋ 许可证门禁 ＋ `.so` 16KB 门禁）；**无 NDK/rootfs 构建**

## 四、决定了不做

| 事 | 为什么 |
|---|---|
| 与主仓合并 | 用户定：**两仓永不合并** |
| 云同步 / 账号 | 不做，纯本地 |
| 多会话（分屏/多终端） | 单会话模型是刻意设计，见主仓私有侧历史文档 |
| 自动更新 rootfs | 环境包冻结在 `rootfs-13.7`；需要新环境时手动发新 Release |
| rar/7z 解包 | 只需 zip/tar 系列（打包解包能力在主仓抱朴里做） |

## 五、运维便条（给以后的自己）

1. **AAR 是手动拷的**：主仓改 `:core` / `:native-core` 后，本仓 `libs/*.aar` **不会自动更新**——升级时手动替换并改版本号。
2. **rootfs 不再自动产出**：主仓的 RootFS 构建步骤已删；需要新环境包时手动跑本仓 `rootfs/build-rootfs.sh`。
3. **特性分支不触发 CI**：要验就跑 PR，或 `workflow_dispatch`。
4. **主仓 Releases 里的旧 rootfs 资产**仍保留（老版本 App 装机要取），但**不再更新**。
