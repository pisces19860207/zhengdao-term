> 分支 `perf/install-verify-t1`（四个提交，父 = `origin/main` `644ca77`；报告自身不写本提交 sha）。

> ⇒ 明确失败并提示，日志留 `FALLBACK_REFUSED`）。硬约束：**不改 Rust 源**。

## 0. 一句话

联网安装路径上，Rust 可用时不再自己把整包哈希一遍——那件事 Rust 解包本来就要做（开解前整读一遍
对账）；Rust 不可用或流水线失败时，现在明确失败并留痕，不再悄悄落回 Java 慢路径。

## 1. 判据（用户 2026-10-28 改订，取代原「总时长降 ≥30%」）

- 原判据**作废**：安装大头在下载与解包，本批能动的只有「解包前多读一遍盘」那一段。
- 新判据：**全量 sha 从「两次」降到「一次」**。证据 = 分段耗时表（下载／全量校验／解包／收尾）
  ＋ `sha256Of 走 Rust/平台回退` 只出现一次（联网首装这条路上现在是 **0 次**，因为 Kotlin 侧
  那次调用被整段去掉，Rust 内部那遍不经过 Kotlin，落 `Rust 解压完成 … sha=` 那一行）。
- 总时长只记录、**不设门槛**。

## 3. P2 改了什么

- `RootfsInstaller.extractArchive`（`terminal-core/…/RootfsInstaller.kt:505`）：
  Rust 不可用 ⇒ 抛 `InstallFailed`；Rust 流水线失败 ⇒ 按 `ShaMismatch`／`EmptyArchive`／其它
  三类分别抛 `InstallFailed`；**没有任何一支落到 Java 慢路径**。
- `refuseFallback`（:584）：`Log.e` ＋ `RunLog.log` 双写 `FALLBACK_REFUSED`（:92 常量）。
  为什么两条都写：`RunLog` 只在 `BuildConfig.DEBUG` 下镜像进 logcat（N-4，`core/…/RunLog.kt:337`），
  release 包里只写 RunLog 等于没人看得见。
- `extractArchiveJava`（:607）：留在仓里当 **Rust 落盘语义的对拍基准**（类型/权限/防穿越/硬链接），
  生产**零调用点**；门禁用 `Regex("extractArchiveJava\\(")` 计数 = 1（只有声明）钉住。
- `InstallPulse.reset()`：T1 之后无调用方，KDoc 已注明身份（对拍基准／单测重跑）。
- 注释对齐（说假话的旧注释全部改掉）：`RootfsInstaller`／`InstallPulse`／`InstallTrace`／`RootfsDelta`
  里「Rust 失败就回退 Java」的表述；增量补丁（`RootfsDelta.applyTo`）改写为同一口径。
- 顺带一处注释真相：`installFromSafUri` 的头注释原写「拷入公共缓存 → **校验** → 解压」，函数体里
  没有任何校验（:1791-1794 自己说明了原因）⇒ 头注释改为实话。

## 6. 设备证据：**未跑**，以及为什么跑不动（这一节是给用户的裁决项）

### 6.1 你的流程在这台手机上取不到 trace

1. 机上那个 0.1.3 是**正式包**：`dumpsys package` ⇒ `flags=0x0`、`pkgFlags` 无 `DEBUGGABLE`、
   `installerPackageName=com.android.chrome`（你从 GitHub 下的）。`run-as` 用不了。
2. `InstallTrace.log()` 只写 `RunLog`；`RunLog` 只在 `BuildConfig.DEBUG` 下镜像 logcat
   （`core/…/RunLog.kt:337`，N-4 制度）。release 包里它落在私有目录 `files/logs/`。
   **⇒ `adb logcat | grep InstallTrace` 必然为空。**
3. 本仓**没有设置页**（台账 T2 未做），所以 RunLog 也没有「导出日志」这个出口。
4. 最要紧的一条：**机上那个包不含本次改动**。在它上面点任何按钮，测的都是旧代码。

### 6.2 而且这个 App 没有「重装环境」按钮

能触发安装的只有三处：首装对话框的「下载」(`startInstall`)、「选择文件」(`installFromSafUri`)、
以及「缓存里已有包时的自动安装」(`promptInstallOnce` → `startInstallFromFile`)。

### 6.3 你给的「改一字节」路线，走 UI 会被绕过（真缺陷，另一批修）

「选择文件」→ `installFromSafUri`（:1760）**没有任何校验值**：它把用户选的包直接交给
`install(appContext, archive)`（:1795，两参重载，`expectedSha = null`），Rust 拿到 null 就只解包不
对账。**⇒ 按原话走那条入口，坏包会被静默装进去，判据 ① 不会成立。**
真正会拦的入口是 `startInstallFromFile`（:1843 `gateForLocal` ＋ :1863 `verifySha256`），
但它只在「App 认为环境没装」时自动触发，没有 UI 入口。

### 6.4 三条可选路（要用户选一条，之后我照办）

- **A 探针包**（推荐）：`debug` ＋ `applicationIdSuffix ".t1probe"`，与你机上那个安装**并存**、
  自己的数据目录 ⇒ **不碰你的 App、不碰你的环境树**；debuggable ⇒ 你的流程（logcat 镜像、
  RunLog 摘要行）原样可跑。代价：多一个 App（用完卸掉）、非 R8 包（不影响下载/解包耗时）。
- **B 同钥可调试正式包**：release 签名 ＋ 临时 `isDebuggable=true`（本机未提交的 build 改动），
  最接近出货包；`install -r` 不卸载、数据保住；跑完把 GitHub 上那版 0.1.3 装回去
  （`zhengdao-term-0.1.3-release.apk` 9,703,112 B，sha256 `a1f02584…` 已核对）。
  代价：证据包在你机上过夜，要装回去一次。
- **C 先不取设备证据**：PR 只带 JVM 与源码级证据，设备三项并到 T3。

## 7. FALLBACK_REFUSED 的证据

- **JVM 侧（已交付）**：`InstallFallbackRefusedTest` 9 例。其中两条是行为级——JVM 里 Rust
  **真的**不可用（`System.loadLibrary` 失败，不需要 mock）：`extractArchive` 抛 `InstallFailed`
  且一个条目都不落盘；`installInto` 失败后不留半截 tmp 树、不碰现有环境（断言
  `!tmpDir.exists()`／`!rootfsDir.exists()`／`trace.extractionPath == ""`／`entries == 0`）。
- **设备侧造不出来**：`FALLBACK_REFUSED` 的前提是 Rust 不可用，而 `.so` 在签名包内无法移除；
  要造得专门打一个缺 `.so` 的包（另一件事，未做）。

## 8. 边界（写进 PR 的那一句）

**本次不改变下载与解包本身的耗时**——改的是「解包前多读一遍盘」和「有可能掉进 Java 慢路径」
这两件事。要再快只能动 Rust 解包（另一单）。
